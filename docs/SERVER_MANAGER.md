# Server manager

Панель: `http://<host>:8088/admin` (прямая ссылка, в меню сайта её нет).

Логин/пароль — `ADMIN_USERNAME` и `ADMIN_PASSWORD` из `.env`. В репозитории
секретов нет; задайте свои значения и не коммитьте `.env`.

Смена логина или пароля сразу завершает все ранее выданные админ-сессии:
токен содержит HMAC-отпечаток текущих учётных данных, поэтому после
перезапуска gateway старые вкладки получают `401 admin_session_expired` и
показывают форму входа. Пользовательские токены это не затрагивает.

## Что можно сделать

- добавить сервер: IP, SSH-порт, логин, пароль, jump-host, bind host,
  fallback-флаг, список микросервисов и портов;
- поставить выбранные сервисы по SSH: control, gateway, parser, catalog,
  library, media, notifier, scheduler;
- посмотреть лог деплоя и здоровье каждого сервиса;
- синхронизировать маршруты или вручную переключить трафик на здоровый сервер;
- посмотреть audit log.

## Как это устроено

```
/admin (React)
   │ admin JWT
   ▼
gateway /api/v1/admin/*  ──►  control :8005
                                   │ SSH / jump host
                                   ▼
                             target server
                             venv + systemd units
```

`control` хранит пароли SSH в зашифрованном виде (Fernet, ключ из
`CONTROL_SECRET_KEY`). Наружу пароли не отдаются и в логи не пишутся. Пароль
нужен только для установки/обновления сервисов.

Деплой идемпотентен: код скачивается из `DEPLOY_SOURCE_URL`, распаковывается в
`/opt/mangapoisk-reborn/src`, обновляется venv, перезаписываются systemd units
`mangapoisk-*.service`, сервисы перезапускаются, затем ждём `/health`.

| Сервис | Порт |

| control | 8005 |
| gateway | 8100 |
| parser | 8101 |
| catalog | 8102 |
| library | 8103 |
| media | 8104 |
| notifier | 8106 |
| scheduler | 8107 (без HTTP) |

Все backend-порты слушают `127.0.0.1`; наружу смотрит только nginx на 8088.
83.141.92.137 используется как SSH jump-host для деплоя, не для трафика
приложения.

## Failover

`control` каждые 30 секунд проверяет `/health` у каждого сервиса. Gateway
раз в 20 секунд забирает registry и переключает parser/catalog/library/media на
первый здоровый endpoint; fallback-серверы идут последними. Если все
недоступны, gateway остаётся на последнем рабочем URL.

Чтобы 83 мог стать fallback: добавьте его в панели, выберите сервисы и порты,
нажмите «Развернуть». Учтите, что SQLite-базы на новом сервере пустые — для
настоящего failover каталога нужна общая БД или репликация. Это следующий шаг,
не обещание текущей версии.

## Ограничения

- SSH-хост-ключ принимается при первом подключении (как в обычном `ssh` с
  `StrictHostKeyChecking=accept-new`). Для параноидального режима добавьте
  pinning позже.
- control должен иметь сетевой доступ к SSH целевого сервера; для 85 это
  делается через 83.
- Деплой перезаписывает `.env` на целевом сервере. Секреты генерируются из
  настроек control; храните `CONTROL_SECRET_KEY` в надёжном месте.
- Автоустановка web-клиента не входит в backend-деплой: `apps/web/dist`
  заливается отдельно в `/opt/mangapoisk-reborn/web` (nginx :8088).
