# Трафик, Яндекс.Метрика и повторная подача в РСЯ (#85)

Статус: реализовано в ветке `feat/metrika-traffic` (worktree `traffic`).
Production не затронут; merge и deploy выполняет lead. Дата подготовки:
**13 ноября 2026**.

Причина задачи: Яндекс РСЯ отклонил площадку с формулировкой «недостаточно
реальных посетителей (менее 100 в неделю)». Повторная подача — **20 ноября
2026, 05:55 (МСК)**. Цель — не «накрутить» счётчик, а привести и измерить
реальных читателей, показать Яндексу работающий сайт и подготовить повторную
модерацию.

## 1. Что сделано

1. **Яндекс.Метрика** подключается build-time переменной `YANDEX_METRIKA_ID`
   (алиас `VITE_YANDEX_METRIKA_ID` для `apps/web/.env`). Номер счётчика не
   захардкожен. Пустое значение полностью отключает загрузчик и запросы к
   `mc.yandex.ru`.
2. **SPA-просмотры**: компонент `TrafficTracker` отправляет `hit` при смене
   маршрута. Учитываются только публичные страницы; `/admin`, читалка
   (`/read`, `/reader`), `/library`, `/profile`, `/login`, `/register` и
   `/offline` не отправляются ни в Метрику, ни во внутренний счётчик.
   Query string и fragment отбрасываются, Webvisor выключен, в параметрах
   только `page_group`.
3. **Внутренний счётчик визитов** без PII: таблица `traffic_visits`
   (`visitor_hash`, `day`, `path_group`, `created_at`), HMAC-SHA256 с серверным
   секретом, уникальность `(visitor_hash, day)`, хранение 90 дней.
4. **Админка**: на вкладке «Обзор» появился блок «Трафик» —
   `unique_visitors_7d`, `unique_visitors_30d`, посетители сегодня, последний
   визит, прогресс к 100/неделю, график за 14 дней и разбивка по разделам.
5. **CSP**: `script-src`, `connect-src` и `img-src` разрешают
   `https://mc.yandex.ru`; `font-src` — `https://yastatic.net`. Остальные
   директивы (`object-src 'none'`, `frame-ancestors 'self'`) не ослаблены.
6. **Юридические тексты**: `/privacy` и `docs/LEGAL.md` описывают Метрику,
   cookie `_ym_uid`/`_ym_d`, внутренний HMAC-счётчик и срок 90 дней.

## 2. Как считаются уникальные посетители

- Браузер генерирует случайный `visitor_id` (тот же локальный идентификатор,
  что и у продуктовой аналитики; это не аккаунт и не email).
- Gateway проверяет, что запрос не от известного бота/краулера, и считает
  `HMAC-SHA256(TRAFFIC_HASH_SECRET, "mangapoisk-traffic-v1\0" + visitor_id)`.
  Сырой `visitor_id` в базу и логи не попадает. Секрет — ключ HMAC; префикс
  `mangapoisk-traffic-v1\0` — domain separation/salt, чтобы тот же id нельзя
  было сопоставить с хэшем из другого сервиса.
- Library вставляет строку `(visitor_hash, UTC day, path_group)` с
  `ON CONFLICT DO NOTHING`. Поэтому несколько страниц за день дают одного
  уникального посетителя, а не несколько.
- `unique_visitors_7d` — число различных `visitor_hash` за сегодня и
  предыдущие 6 календарных дней (UTC).
- `unique_visitors_30d` — то же за 30-дневное скользящее окно.
- `last_visit_at` — максимальный `created_at`.
- `path_group` фиксируется при первом визите дня: `home`, `catalogue`,
  `manga`, `collection`, `sources`, `legal`, `profile`, `other`.
- `TRAFFIC_RETENTION_DAYS=90`: library периодически (не чаще раза в час)
  удаляет строки старше 90 дней.

Это внутренняя оценка, а не замена Метрике: Яндекс видит свои визиты, админка
показывает прогресс и позволяет понять, хватает ли реальной аудитории.

### Схема `traffic_visits`

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | UUID | технический первичный ключ |
| `visitor_hash` | `varchar(64)` | HMAC-SHA256 случайного id; необратим без секрета |
| `day` | `date` | UTC-день визита |
| `path_group` | `varchar(32)` | группа публичной страницы |
| `created_at` | `timestamptz` | время первого визита дня; для `last_visit_at` |

Индексы: уникальный `(visitor_hash, day)`, `(day)`, `(day, path_group)`.
IP-адрес, user-agent, email, user id, полный URL и referrer не хранятся.

## 3. Переменные окружения

| Переменная | Где | Обязательно | Смысл |
|---|---|---|---|
| `YANDEX_METRIKA_ID` | build web / Docker build arg | Да, для Метрики | Номер счётчика, только цифры. Пусто = загрузчик выключен |
| `VITE_YANDEX_METRIKA_ID` | `apps/web/.env` | Альтернатива | То же значение для локальной сборки |
| `TRAFFIC_HASH_SECRET` | gateway + library | Рекомендуется | Секрет HMAC. Пусто = fallback на `JWT_SECRET` |
| `TRAFFIC_RETENTION_DAYS` | library | Нет | Срок хранения визитов, по умолчанию 90 |

`YANDEX_METRIKA_ID` — **build-time** значение: после изменения нужно
пересобрать web-образ, одного перезапуска контейнера недостаточно.

```bash
# .env
YANDEX_METRIKA_ID=12345678
TRAFFIC_HASH_SECRET=<длинная случайная строка>
TRAFFIC_RETENTION_DAYS=90

docker compose build web
docker compose up -d web gateway library
```

Проверка после сборки:

```bash
curl -s https://<host>/ | grep -o 'mc.yandex.ru' || true
# В SPA скрипт появляется после выполнения JS. Надёжнее открыть DevTools →
# Network и убедиться, что tag.js загружается с mc.yandex.ru, а в HTML нет
# захардкоженного номера счётчика.
```

## 4. План набора 100+ реальных уникальных в неделю

Никаких ботов, автопосещений, VPN-ферм и накрутки: это нарушает правила РСЯ и
даёт отклонение повторно. Нужны реальные читатели.

1. **Домен и HTTPS.** `nip.io` выглядит как тестовый стенд. Подключить
   нормальный домен, HTTPS, `PUBLIC_WEB_URL`, canonical/OG и
   `VITE_SITE_URL`; проверить редиректы.
2. **Яндекс.Вебмастер.** Добавить сайт, подтвердить `YANDEX_VERIFICATION`,
   отправить `sitemap.xml`, проверить индексацию, битые обложки и пустые
   карточки. Раздел «Диагностика» — без критичных ошибок.
3. **Google Search Console.** Подтвердить `GOOGLE_SITE_VERIFICATION`,
   отправить sitemap, проверить Mobile usability и Core Web Vitals.
4. **Контент и SEO.** Канонические URL `/manga/{id}-{slug}`, уникальные
   title/description, отсутствие 18+ в публичном sitemap и публичной
   индексации, `robots.txt`, `ads.txt`, скорость загрузки.
5. **Telegram/VK/тематические сообщества.** Публиковать анонсы глав и
   подборок в тематических каналах и чатах, где это разрешено правилами.
   Не спамить и не покупать «посещения».
6. **Постоянные читатели.** Просить друзей/знакомых читать реально, а не
   открывать страницу по таймеру. Лучше 100 живых людей за неделю, чем
   тысячи ботов.
7. **Метрика.** Убедиться, что счётчик активен, визиты видны, цель
   «100 уникальных в неделю» отслеживается в админке и в Метрике.
8. **Обратная связь.** Отвечать на комментарии/письма, исправлять битые
   страницы: удержание важнее разового всплеска.

## 8. Ограничения

- Внутренний счётчик — оценка, а не юридически значимая статистика. Яндекс
  считает визиты по своим правилам (cookie, блокировщики, DNT).
- HMAC защищает идентификатор, но не делает таблицу «анонимной навсегда»:
  при компрометации секрета и наличии исходных id возможна корреляция.
  Секрет хранить только в окружении, не в git.
- Если `TRAFFIC_HASH_SECRET` не задан, используется `JWT_SECRET`. Смена
  секрета обнуляет связность старых хешей (уникальность за прошлые дни
  сохранится, но тот же посетитель будет выглядеть новым).
- Таблица создаётся автоматически при старте library (`create_all`).
  Отдельная миграция не требуется; для PostgreSQL используется тот же
  SQLAlchemy-метаданные.
