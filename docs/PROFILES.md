# Профили, XP, уровни, звания и достижения (#47)

Статус: работает в production с v1.3.0 (13.11.2026). Публичные профили
индексируются по умолчанию; sitemap профилей пока не включает (#47).

Документ описывает публичные профили MangaPoisk Reborn, правила геймификации,
приватность и модерацию. Реализация переиспользует retention-слой v1.2:
`reading_days`, `reading_progress`, `compute_streak` и существующие analytics
events. Отдельная аналитика профилей не добавлялась.

## 1. Публичная карточка

Маршрут SPA: `/u/{username}`. API: `GET /api/v1/users/{handle}`, где `handle`
— ник или UUID пользователя. Внутренний вызов library:
`GET /internal/profiles/{handle}` с `X-Viewer-Id` от gateway.

Карточка содержит:

- отображаемое имя, `@username`, инициалы вместо аватара, био, дату регистрации;
- уровень, звание, прогресс до следующего уровня/звания;
- агрегированную статистику: главы, тайтлы, завершённые тайтлы, дни чтения,
  текущая и лучшая серия;
- любимые жанры (по последним 500 главам, один голос на тайтл);
- достижения: гостям — только полученные, владельцу — все с прогрессом;
- последние события: прочитанная глава, завершённый тайтл, достижение.

Публичный ответ **не содержит** email, IP, user agent, внутренний `user_id`,
роль, refresh-токены и точные метки времени чтения. События и достижения отдают
только календарную дату (`occurred_on`, `unlocked_on`); точные `created_at` /
`unlocked_at` видит только владелец.

### Индексация (решение владельца, 2026-11-13)

- Публичные профили **индексируются по умолчанию**: `robots = index,follow`,
  canonical `/u/{username}`, OG/Twitter-мета, JSON-LD `ProfilePage` + `Person`.
- В настройках есть переключатель «Индексировать в поиске». Если владелец его
  выключил, карточка остаётся публичной, но получает `noindex,nofollow`.
- Если владелец скрыл профиль (`is_private`) **или любой из разделов**
  «статистика / события / достижения», применяется более безопасный вариант:
  гости получают `404`, карточка получает `noindex,nofollow`. Владелец
  по-прежнему видит свой профиль и может вернуть разделы.
- Ответ владельцу всегда `Cache-Control: private, no-store` и
  `X-Robots-Tag: noindex, nofollow`, потому что содержит точные timestamp'ы.
- Публичный ответ кэшируется на 60 секунд (`public, max-age=60`), чтобы смена
  приватности применялась без деплоя.
- Профили **не добавлены в sitemap** в этой итерации: сначала нужно решить
  вопрос масштабирования и модерации публичных страниц. Canonical и robots уже
  корректны, поэтому добавление в sitemap не потребует менять API.

## 2. XP и уровни

Правила намеренно маленькие и прозрачные:

| Источник | XP | Ключ идемпотентности | Ограничение |
| --- | ---: | --- | --- |
| Первое открытие главы | 10 | `chapter:{chapter_id}` | Не более 100 XP за UTC-день |
| Бонус за день чтения | 5 | `day:{YYYY-MM-DD}` | Один раз за UTC-день |
| Завершение тайтла | 25 | `finish:{manga_id}` | Один раз за тайтл |

- XP — append-only ledger `xp_events`; уникальный индекс `(user_id, dedupe_key)`
  делает повторные открытия, повторную отправку прогресса и повторный финиш
  no-op. Удаление прогресса не удаляет XP.
- Суточный лимит считается по `chapter`-записям текущего UTC-дня. Дневной бонус
  и финиш в лимит не входят.
- Backfill не требуется: XP начинается с момента деплоя. Старые прочитанные
  главы не начисляются задним числом.
- Уровень: `xp_for_level(L) = 25 * L * (L - 1)`, максимум 99.
  `L2 = 50`, `L3 = 150`, `L4 = 300`, `L10 = 2250`, `L20 = 9500`.
- Завершение тайтла засчитывается только если: глава принадлежит этому тайтлу,
  её номер — максимальный числовой номер среди глав, и страница больше или
  равна `page_count` из каталога. Клиентский `total_pages` для финиша не
  используется, чтобы нельзя было подделать завершение.

## 4. Достижения

Каталог засеян в коде (`ACHIEVEMENTS`) и не требует миграции. Уникальный индекс
`(user_id, code)` гарантирует однократную выдачу; событие `achievement`
создаётся только при реальной вставке.

| Код | Название | Метрика | Порог |
| --- | --- | --- | ---: |
| `first_chapter` | Первая глава | главы | 1 |
| `ten_chapters` | Десять глав | главы | 10 |
| `fifty_chapters` | Пятьдесят глав | главы | 50 |
| `hundred_chapters` | Сотня | главы | 100 |
| `five_hundred_chapters` | Марафонец | главы | 500 |
| `first_title` | Первый тайтл | тайтлы | 1 |
| `ten_titles` | Коллекционер | тайтлы | 10 |
| `fifty_titles` | Библиотекарь | тайтлы | 50 |
| `first_finish` | До конца | завершённые | 1 |
| `ten_finishes` | Завершитель | завершённые | 10 |
| `first_day` | Первый день | дни чтения | 1 |
| `week_streak` | Неделя с мангой | серия | 7 |
| `month_streak` | Месяц с мангой | серия | 30 |
| `level_5` | Уровень 5 | уровень | 5 |
| `level_10` | Уровень 10 | уровень | 10 |
| `level_25` | Уровень 25 | уровень | 25 |

Серии для достижений считаются по UTC-дням (детерминированно и без зависимости
от часового пояса клиента). В карточке статистики серия показывается в
часовом поясе владельца/гостя через существующий `compute_streak`.

## 5. События

Таблица `profile_events`, уникальный `(user_id, dedupe_key)`:

- `chapter_read` — `chapter:{chapter_id}`;
- `title_finished` — `finish:{manga_id}`;
- `achievement` — `achievement:{code}`.

Название тайтла, глава, постер и жанры денормализуются из **доверенного ответа
каталога** на gateway. Публичный клиент не может подменить эти поля: gateway
перезаписывает их перед внутренним вызовом library.

Публичная лента по умолчанию включена (решение владельца об индексации), но
отдаёт только дату без точного времени. Владелец может скрыть события; это,
согласно выбранному безопасному варианту, скрывает всю карточку от гостей и
убирает её из индекса.

## 6. Приватность и кэширование

Настройки (`user_profiles`):

| Поле | По умолчанию | Поведение |
| --- | --- | --- |
| `is_private` | `false` | `true` → гости получают 404, noindex |
| `show_stats` | `true` | `false` → гости 404, noindex |
| `show_events` | `true` | `false` → гости 404, noindex |
| `show_achievements` | `true` | `false` → гости 404, noindex |
| `indexable` | `true` | `false` → карточка публична, но noindex |

Публичные ответы: `Cache-Control: public, max-age=60`,
`X-Robots-Tag: index, follow` либо `noindex, nofollow`. Ответы владельца:
`private, no-store` + `noindex, nofollow`. Приватный/скрытый профиль отдаёт тот
же 404, что и несуществующий, чтобы не раскрывать факт его существования;
404 для профилей помечается `Cache-Control: no-store`.

## 7. Модерация

- `display_name`: 1–48 символов, схлопывание пробелов, запрет control-символов и
  `<`/`>`; хранится в `users.display_name`.
- `username`: 3–24 символа, `[a-z0-9_]`, зарезервированные имена (`admin`, `api`,
  `me`, `support`, …) запрещены; хранится в `user_profiles.username`, уникален.
- `bio`: до 280 символов, переводы строк нормализуются, HTML-теги запрещены.
- Жалоба: `POST /api/v1/users/{handle}/report`, причина 3–500 символов,
  открытые жалобы от одного пользователя на одного и того же пользователя
  дедуплицируются.
- Блокировка: `POST`/`DELETE /api/v1/users/{handle}/block`. Блокировка
  взаимная по видимости: профиль исчезает для обеих сторон.
- Админ-очередь: `GET /api/v1/admin/profile-reports`,
  `PATCH /api/v1/admin/profile-reports/{id}`.
- **Загрузка аватаров не добавлялась**: только инициалы. Для загрузки нужен
  безопасный pipeline (валидация изображения, лимиты, модерация, антивирус,
  CDN). Это отдельное решение.

## 8. API

Публичные:

- `GET /api/v1/users/{handle}` — карточка; `timezone` опционален для серии.
- `GET /api/v1/users/{handle}/report` — нет; жалоба ниже.
- `POST /api/v1/users/{handle}/report` — `{ "reason": "..." }`.
- `POST /api/v1/users/{handle}/block`, `DELETE .../block`.

Авторизованные:

- `GET /api/v1/me/profile` — полный профиль владельца.
- `PATCH /api/v1/me/profile` — частичное обновление.
- `GET /api/v1/me/events?limit=30` — точные timestamp'ы владельца.

Админ:

- `GET /api/v1/admin/profile-reports?status=open|resolved|dismissed|all`.
- `PATCH /api/v1/admin/profile-reports/{id}` — `{ "status": "resolved" }`.

## 9. Схема БД

Новые таблицы создаются через `create_all` при старте library; отдельных
Alembic-миграций в проекте нет. Существующие таблицы не меняются, backfill не
нужен.

- `user_profiles` — ник, био, приватность, `indexable`; строка создаётся лениво
  при регистрации/входе/первом открытии профиля.
- `xp_events` — append-only XP ledger.
- `profile_events` — публичная лента.
- `user_achievements` — выданные достижения.
- `profile_reports` — жалобы.
- `profile_blocks` — блокировки.

## 10. Frontend и mobile

- `/u/{username}` — публичная карточка (web + Capacitor-оболочка `apps/mobile`,
  которая собирает тот же React-код).
- `/profile` — настройки: публичные поля, приватность, достижения, события.
- `/admin` — панель «Модерация профилей».
- Адаптив: 1440×900 (двухколоночная карточка) и 390×844 (одна колонка,
  горизонтальные действия, сетка статистики 2×3).
- Доступность: заголовки, `role="progressbar"`, фокус в модалке жалобы,
  текстовые подписи к иконкам.

## 12. Решения и открытые вопросы

Решено:

- публичная индексация по умолчанию, canonical + OG/Twitter + JSON-LD;
- при скрытии любого раздела — 404 гостям и noindex (безопасный вариант);
- аватары — только инициалы;
- события — дата без точного времени; email/IP/user_id не отдаются;
- sitemap профилей пока не добавляем;
- социальная лента (чужие профили в ленте) не делалась — только личная история
  и события на карточке.

Требует решения владельца:

1. Загрузка аватаров: нужен ли pipeline с модерацией или остаются инициалы?
2. Публичная индексация: оставить включённой по умолчанию или вернуть opt-in?
3. Социальная лента: нужна ли подписка на события других пользователей?
4. Sitemap профилей: включать после появления модерации/лимитов?
