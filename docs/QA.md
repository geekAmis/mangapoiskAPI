# QA / user testing

Дата: 11 ноября 2026. Проверяли на реальном сервере
`https://85.192.37.58.nip.io:8443` и на телефоне TECNO KL6 (Android, 1080×2460).

## Дополнение к 1.1.0 (main)

Реализовано в `main`; production-скриншоты приложены, но перед публикацией
релиза нужен отдельный финальный прогон:

- офлайн-библиотека web/Capacitor: скачивание главы и тайтла, очередь,
  докачка, удаление, офлайн-читалка (`prod-library-downloads-mobile.png`);
- 16 dancing-GIF, inline-спиннеры и boot-loader (`prod-boot-loader.png`,
  `prod-dancing-loader.png`);
- админ-сессии: после смены `ADMIN_PASSWORD` старый токен должен получать
  `401 admin_session_expired`;
- админ-вход: 5 неудачных попыток с одного IP за 5 минут дают
  `429 admin_rate_limited`, токен живёт `ADMIN_TOKEN_MINUTES`;
- rate limit берёт `X-Real-IP`, а media режет private/metadata/redirect SSRF;
- server manager: частичный деплой, jump-host, health удалённых узлов;
- приоритетный registry: fallback последним, jump-хосты после обычных;
- prepare-фаза загрузок: `POST/GET /manga/{id}/prepare`, батчи по 5 глав,
  сохранение очереди между перезапусками;
- комментарии к тайтлам: ответы, лайки, спойлеры, жалобы, модерация,
  уведомления;
- cookie источников: ручное значение и импорт `.har` в `/admin`; значение
  cookie не возвращается в API и не попадает в логи;
- archive LRU около 25 GiB; метаданные и обложки не вытесняются;
- HTTPS на `https://85.192.37.58.nip.io:8443`; HTTP `:8088` — fallback.

Перед публикацией `v1.1.0` нужны `pytest`, `ruff`, `npm run build` и зелёный
CI на `main`, а также повторная проверка service worker на HTTPS.

### Переводы и источники

- MangaLib detail через `api.imglib.info` + `Site-Id: 1` возвращает русские
  названия; страницы идут с `img3.cdnlibs.org`;
- фильтр переводов по `source/translator/count` отдаётся variants-endpoint;
- «Во всеоружии»: MangaPoisk 274 главы, MangaLib 22 главы с командами
  ArticaProject/Hexe/Ньюби — variants работает;
- Remanga adapter реализован; доступ к API включается оператором с учётом
  robots и разрешения источника, cookie задаётся в админке или через `.env`;
- ReadManga/MangaDex остаются best-effort/выключенными из-за сети.

### Серверный архив

- глава 8 страниц MangaPoisk сохранена как ZIP 3.5 MB (страницы > 1 MB);
- повторный запрос страницы идёт через archive endpoint, не в источник;
- маленькие главы сохраняются BLOB-ами в SQLite;
- «скачать всё» ставит в очередь архивирование всех глав (endpoint
  `/api/v1/manga/{id}/warm`).

## Известные ограничения

- HTTPS настроен: `https://85.192.37.58.nip.io:8443`; HTTP `:8088` оставлен
  для совместимости. Для release APK нужен HTTPS endpoint.
- Android release APK не подписан.
- Нет iOS-сборки.
- SQLite на одном сервере; для нескольких инстансов нужна общая БД или
  репликация (репликация ещё в разработке и не включена в production).
- MangaLib отдаёт только одну ветку перевода на главу (первую команду), не все
  ветки сразу.
- Новые главы кэшируются только после первого открытия (так и задумано).
