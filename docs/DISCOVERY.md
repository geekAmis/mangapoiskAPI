# Discovery: «Похожее» и публичные подборки

Документ описывает выдачу соседних тайтлов и публичные подборки, которые
появились в рамках задачи
[#43](https://github.com/geekAmis/mangapoiskAPI/issues/43).  Всё работает без
ML и без внешних рекомендательных сервисов: только данные каталога и
редакционные решения.

## 1. Блок «Похожее» на странице тайтла

`GET /api/v1/manga/{id}/related` возвращает три независимых набора:

- `series` — явные связи «часть цикла», порядок задан редактором;
- `related` — явные проверенные связи между тайтлами;
- `similar` — эвристическая выдача «Похожее», 6–12 карточек.

Эвристика считается в `services/catalog/app/discovery.py::similar_score`.
Оценка нормализована в `0..1`, веса фиксированы:

| Признак | Вес | Как считается |
|---|---:|---|
| Жанры | 0.52 | Jaccard по нормализованным slug-ам жанров |
| Рейтинг | 0.18 | `rating / 10` |
| Год | 0.10 | линейно, расхождение 20+ лет даёт 0 |
| Тип | 0.08 | точное совпадение `content_type` |
| Число глав | 0.07 | близость `log1p(chapters)` |
| Популярность | 0.05 | `log1p(rating_count)`, только тай-брейкер |

Дополнительно ответ сортируется по убыванию рейтинга, числа оценок, затем по
названию и `id`.  Поэтому выдача детерминирована при неизменном каталоге и не
зависит от порядка строк в базе.

### Исключения и чистота выдачи

Из `similar` всегда исключаются:

- сам тайтл и все его source-варианты (общий `group_key`);
- пустые заглушки: `chapters_count = 0`, отсутствие строк глав, пустой
  `poster_url` или пустое название;
- уже прочитанное: история аккаунта (до 100 записей) и локальная история
  анонимного клиента, переданная в `history`;
- явные `series`/`related` связи, чтобы не дублировать курируемые блоки.

Клиент передаёт локальные id в `history` (comma-separated UUID, до 4096
символов).  Для авторизованного пользователя gateway сам добавляет серверную
историю из library и помечает ответ `Cache-Control: private`.  Анонимный ответ
можно кэшировать: `public, max-age=120`.

Если в каталоге меньше шести подходящих тайтлов, возвращается столько, сколько
есть; карточки-заглушки не добавляются.  Это осознанный компромисс: лучше
меньше, но все с обложкой и главами.

## 2. Публичные подборки

`GET /api/v1/collections` — превью для главной (до 24 подборок, по умолчанию
12 карточек в каждой).  `GET /api/v1/collections/{slug}` — страница подборки
(до 60 карточек).  Обе ручки публичные, кэшируются на 60 секунд с
`stale-while-revalidate=300`.

### Встроенные умные подборки

Создаются один раз при старте catalog-сервиса
(`seed_smart_collections`).  Редактор может переименовать, скрыть,
переставить или удалить подборку; повторный старт не перезаписывает
отредактированные поля и не воскрешает удалённые подборки.

| Slug | Правило | Логика |
|---|---|---|
| `weekly-best` | `weekly_best` | главы за 7 дней, сортировка по рейтингу/оценкам; при нехватке — окно 30 дней |
| `beginners` | `beginners` | не 18+, рейтинг ≥ 7.0, 10–500 глав, «понятные» жанры; мягкий fallback при нехватке |
| `completed` | `completed` | `status_key = completed`, сортировка по популярности |
| `short` | `short` | 1–30 глав, свежие обновления |
| `new` | `new` | недавно появились в каталоге, затем рейтинг |

Все правила:

- фильтруют пустые заглушки и требуют обложку + хотя бы одну главу;
- дедуплицируют source-варианты по `group_key`;
- имеют детерминированные тай-брейкеры (название, `id`);
- не смешивают статусы: «Завершённые» никогда не показывает онгоинги,
  «Короткие» — длинные тайтлы.  Если подходящих тайтлов нет, подборка просто
  не попадает в публичный список; главная остаётся с рекомендациями и другими
  подборками.

Умная подборка может быть создана и вручную в админке: достаточно выбрать
`kind=smart` и одно из правил.  Ручная (`kind=manual`) хранит явный
упорядоченный список тайтлов.

### Ручные подборки

- Порядок задаётся полем `position` у элементов (шаг 10), затем `created_at`.
- Дубликаты и пустые тайтлы не добавляются: API отвечает
  `collection_item_ineligible` или игнорирует повтор.
- Пустая ручная подборка остаётся пустой: API не подмешивает случайные тайтлы.
- Удаление подборки не удаляет тайтлы каталога; аудит сохраняется.

## 3. Редакторская админка

Все ручки требуют admin-JWT и проксируются gateway в catalog:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/admin/collections` | все подборки, включая скрытые |
| POST | `/api/v1/admin/collections` | создать |
| PATCH | `/api/v1/admin/collections/{id}` | изменить поля/правило/видимость/позицию |
| DELETE | `/api/v1/admin/collections/{id}` | удалить |
| POST | `/api/v1/admin/collections/{id}/items` | добавить тайтл `{manga_id}` |
| DELETE | `/api/v1/admin/collections/{id}/items/{manga_id}` | убрать тайтл |
| PUT | `/api/v1/admin/collections/{id}/order` | `{manga_ids:[...]}` |
| GET | `/api/v1/admin/collections/audit?limit=` | журнал действий |

Audit (`manga_collection_audit`) хранит только действие, `collection_id`,
slug/название, `manga_id`/название и время.  Пароли, токены, IP и
пользовательские данные туда не пишутся.  Журнал доступен в панели «Подборки».

Изменения применяются без рестарта: после каждой мутации очищается
in-process кэш discovery, а клиентский React Query инвалидирует
`['collections']`.

## 4. Кэширование и инвалидация

- `collection_cache` — 300 секунд, до 128 ключей;
- `similar_cache` — 300 секунд, до 1024 ключей;
- ключ включает seed, отсортированную историю, явные исключения и лимит;
- любой импорт (`import_detail`/`import_summary`) вызывает
  `clear_discovery_cache()`; это же делают все admin-мутации;
- gateway отдаёт `Cache-Control` для публичных ручек и `private` для
  персонализированного «Похожего».

При импорте очищается и старый `recommendation_cache`: каталог изменился,
поэтому все производные полки должны пересчитаться.

## 5. Метрики

Клиент пишет события через существующий retention-пайплайн
(`POST /api/v1/analytics/events`), без новых полей и без PII:

- `impression` — полка/сетка стала видимой (IntersectionObserver, один раз);
- `click` — клик по карточке;
- `surface` — `collection_<slug>` (до 32 символов) или `manga_related`.

Агрегаты доступны администратору:

`GET /api/v1/admin/analytics/surfaces?days=30` →

```json
{
  "days": 30,
  "generated_at": "2026-11-13T00:00:00Z",
  "items": [
    {"surface": "collection_weekly-best", "impressions": 1200, "clicks": 84, "ctr": 0.07}
  ]
}
```

Считаются только `impression`/`click` за окно 1–90 дней, пустой `surface`
игнорируется.  `client_id` остаётся случайным device-id и не связывается с
аккаунтом.  События отправляются пакетно и не блокируют рендер страницы.

## 6. Производительность и надёжность

- Публичные ручки читают только каталог; запись (seed) выполняется на старте
  сервиса, а не на каждый запрос.
- Списки ограничены: 600 кандидатов на умную полку, 60 элементов на
  подборку, 12 карточек «Похожего».
- Кэш тёплый после первого запроса; home-запрос подборок не блокирует
  рекомендации.
- Если каталог временно пуст или подборка скрыта, публичный API возвращает
  пустой список/404, а фронтенд скрывает секцию или показывает пустое
  состояние — без падений и CLS.
