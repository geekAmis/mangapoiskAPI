# Retention: продолжение чтения, рекомендации, серии, streak

Статус: retention-слой работает в production с v1.2/v1.3 (13.11.2026);
исправление resume-prompt #81 входит в v1.3.0.

Этот документ описывает retention-слой, добавленный в ветке `feat/retention`.
Он не меняет контракты существующих эндпоинтов и не добавляет внешней
аналитики.

## 1. Продолжение чтения

- Авторизованный пользователь: таблица `reading_progress` (одна строка на
  `user_id + manga_id`) плюс `reading_days` для streak.
- Анонимный пользователь: `localStorage["mp:progress:v1"]`. Запись содержит
  снимок тайтла/главы, страницу, `total_pages`, `owner_id` и время чтения.
- `owner_id = null` — анонимная запись; при входе она сливается с аккаунтом.
  Записи другого аккаунта на этом устройстве не подмешиваются.
- `POST /api/v1/library/progress/merge` принимает `items` и `read_days`.
  Сервер оставляет более новую позицию по каждому тайтлу, поэтому старое
  устройство не может откатить прогресс. Повторный merge идемпотентен.
- Сортировка — по времени последнего чтения. CTA ведёт на
  `/reader/{chapter_id}?page={page}`.
- В читалке подсказка «Продолжить со страницы N?» показывается только после
  1.8 с бездействия и только если сохранённая страница впереди текущей более
  чем на одну. Любое взаимодействие (колесо, touch, скролл, смена страницы,
  клик по странице, клавиатура) сразу скрывает подсказку и включает
  сохранение прогресса — медленный ответ `GET /library/progress` не может
  показать её поверх уже начатой главы.

## 2. Рекомендации

`GET /api/v1/recommendations?limit=12&seed_ids=...&exclude=...&seed_manga_id=...`

- Для аккаунта учитываются история и закладки. Для анонима — `seed_ids` из
  localStorage.
- Эвристика: жанровое совпадение (история/закладки/seed) + рейтинг + свежесть
  последней главы + популярность. Без ML.
- Уже прочитанные тайтлы исключаются по `id` и по нормализованной группе
  названий (чтобы не показать другой источник того же тайтла).
- Тайтлы без глав не попадают в выдачу.
- Холодный старт: популярное/рейтинг/свежесть без истории.
- Ответ кэшируется на 120 секунд в catalog-сервисе (ключ включает seed-иды,
  закладки, исключения и лимит). На клиенте `staleTime` — 5 минут.

## 3. Серии и явные связи

- Таблица `manga_relations`: `from_manga_id`, `to_manga_id`,
  `relation` (`series` / `related`), необязательный `series_key`.
- Связи не угадываются по названиям. Их добавляет админ/seed hook:
  `PUT /api/v1/admin/manga/{manga_id}/relations`
  ```json
  {"items":[{"to_manga_id":"...","relation":"series","series_key":"cycle-x"}]}
  ```
- Публичный `GET /api/v1/manga/{manga_id}/related` возвращает `series` и
  `related`; на странице тайтла это блоки «Серия» и «Похожее».
- Если в `series_key` объединены A-B и B-C, открытие B показывает A и C.

## 4. Streak

- `reading_days` хранит по одной строке на пользователя и UTC-день с
  максимальным временем чтения.
- Streak считается в часовом поясе клиента: UTC-таймстемпы конвертируются в
  локальные даты, дубликаты схлопываются. Поэтому смена устройства не рвёт
  серию, а переход через полночь/DST не создаёт ложный разрыв.
- Если сегодня ещё не читали, серия не сбрасывается до конца локального дня.
  Штрафов и уведомлений нет, только счётчик и 14-дневная полоска.
- `GET /api/v1/library/streak?timezone=Europe/Moscow`.
- Анонимный streak считается из `localStorage["mp:reading-days:v1"]`; при
  входе эти дни отправляются в `progress/merge` и продолжаются в аккаунте.

## 5. Аналитика

- `POST /api/v1/analytics/events` — публичный приём батча до 50 событий:
  `impression`, `click`, `read_start`, `read_complete`, `finish`.
- Поля: `event`, `dedupe_key`, случайный `client_id` (локальный id устройства),
  `surface`, опциональные `manga_id`/`chapter_id`.
- **Нет** IP, User-Agent, account id, свободного текста и внешних SDK.
  Клиент уважает `Do Not Track` / `Global Privacy Control`.
- `dedupe_key` уникален: повторная отправка не создаёт дубль.
- `GET /api/v1/admin/analytics/retention?days=30` — недельные когорты и
  D1/D7/D30 по анонимным `client_id`.

## 6. Решения на ревью

- Награды за streak: сейчас только счётчик, без бонусов и напоминаний.
- Внешняя аналитика (Метрика/Plausible): не добавлялась, только внутренние
  события.
- Источник серий: только явный seed/admin hook; автоматическая эвристика по
  названиям намеренно не включена.
